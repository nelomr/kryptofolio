## 4. Commit 1 — `TaxDerivativeEntity` (5 fields, 9 non-test consumers). Requires `align-derivatives-pnl-contract`

Fields: `amount`, `tradePrice`, `realizedPnl`, `fees`, `funding` (`FiscalEntities.ts:52-60`). First
on purpose: smallest surface, and it carries the only real arithmetic in scope, so every idiom this
change introduces is settled here.

**The emitter, and D15's verdict: all five fields become `Money | null`.** After
`align-derivatives-pnl-contract`, `getFuturesDerivatives()` reads `/api/tax/transactions/futures`,
whose emitter is `LedgerFuturesTransaction` — `amount?`, `trade_price?`, `realized_pnl?`,
`fee_amount?`, `funding_amount?`, each an optional `PreciseAmount` (`ILedgerPort.ts:62-80`) mapped
from a nullable TEXT column by `SQLiteLedgerAdapter.ts:233-258` (`row.x ? toPreciseAmount(...) :
undefined`). A source-stated zero is persisted and arrives as the string `'0'`, so `undefined` is
reached only by a SQL NULL, and that NULL means unknown / discarded / unresolved — never a measured
zero. Every `?? 0` in the DTO is therefore a live fabrication on real rows. The old split (three
non-nullable, two nullable) came from the deleted `DerivativesPnl` aggregate and is void.

**The backend is not touched in this phase** — but not because it is unreachable: the fabrication is
entirely in the frontend's `?? 0` (D15). Do not open `SQLiteLedgerAdapter` or a DuckDB view for this.
D15 records two real emitter defects found while measuring (no writer populates `trade_price`; the
truthiness gate would collapse an empty string to `undefined`) as a futures-ingestion change.

**Test through the real adapter, deliberately.** The old instruction to exercise the schema in
isolation was a workaround for a defect `align-derivatives-pnl-contract` fixes: the schema no longer
mismatches the route, so the table renders real rows and the adapter path is exactly what must be
covered.

**Nomenclature, which both changes have already got wrong once.** The *emitter's* funding type is
`FUNDING_FEE`, one of `FuturesTxType`'s four members
(`packages/shared-types/src/schemas/ledger.ts:19-23`). `FUTURES_FUNDING` is the **frontend entity's**
value (`FiscalEntities.ts:28-32`), produced by `mapFuturesType`. A test feeding `FUTURES_FUNDING` as
a *wire* input asserts a shape no route sends — a vacuous pass. Wire fixtures use `FUNDING_FEE`;
entity-level assertions use `FUTURES_FUNDING`.
