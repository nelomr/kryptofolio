# Contributing to Kryptofolio

Thank you for your interest in contributing to Kryptofolio!

## ⚠️ Current Project Status

Currently, this repository serves as a personal portfolio project and **does not accept external Pull Requests** at this time. I (the repository owner) am the only one actively making changes to the main codebase.

However, since this repository is open-source and uses the [AGPL-3.0 License](LICENSE):
- You are more than welcome to **fork** the repository.
- You can use the code for your own projects, experiments, or learning.
- You can freely study the architecture and implementation details.

---

## 📋 How to Contribute (Current Options)

Even though we are not accepting direct code contributions yet, we welcome community feedback! You can contribute in the following ways:

### Reporting Bugs
If you find a bug:
1. Check if the bug has already been reported in the GitHub [Issues](https://github.com/nelomr/kryptofolio/issues).
2. If not, create a new issue with:
   - A clear, descriptive title.
   - Steps to reproduce the issue.
   - Expected vs. actual behavior.
   - Your environment details (OS, browser, versions, etc.).

### Suggesting Features
If you have ideas to improve Kryptofolio:
1. Check existing issues to see if a similar feature has already been suggested.
2. Open a new issue describing:
   - The problem you are trying to solve.
   - Your proposed solution.
   - Any alternatives you've considered.

## 🔮 Future Code Contributions

In the future, when the project opens to external developers, the following rules will apply:

### Contributor License Agreement (CLA)
We will require a Contributor License Agreement (CLA) for all code contributions. By submitting a pull request, you confirm that you have read, understood, and agree to the terms in [CLA.md](CLA.md). PRs without CLA agreement will not be merged.

### Submitting Code
Once code contributions are open, the workflow will be:
1. Fork the repository.
2. Create a feature branch (`git checkout -b feature/amazing-feature`).
3. Make your changes.
4. Ensure all unit tests pass and code complies with the project's architectural guidelines (strict Hexagonal Architecture).
5. Commit your changes with clear, Conventional Commit messages.
6. Push to your fork (`git push origin feature/amazing-feature`).
7. Open a Pull Request.

### Development Setup
See the [README.md](README.md) for detailed setup instructions.
